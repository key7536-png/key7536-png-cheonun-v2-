# 유튜브 사주 대본 스킬

주제 한 줄을 받아서, 5분짜리 "상담 재연" 영상 대본과 그 대본을 유튜브에 올리는 데 필요한 모든 것
(스토리보드, 업로드 정보)을 완성해 HTML 한 장으로 넘겨준다. 사용자는 이 산출물을 그대로 복붙해서
TTS·이미지 생성·유튜브 업로드에 바로 쓴다.

## 왜 이런 구조인가 (먼저 읽을 것)

- **왜 상담사-의뢰인 대화체인가**: 혼자 설명하는 나레이션보다, 상담사가 의뢰인에게 사주를 풀어주고
  의뢰인이 가끔 되묻는 구조가 실제 상담을 몰래 듣는 느낌을 준다. 의뢰인의 짧은 질문이 자연스럽게
  마이크로 오픈 루프 역할을 하고, 대사 길이에 리듬을 만들어 리텐션에 유리하다. 자세한 이유와 어투
  규칙은 `references/dialogue-format-guide.md` 참고 — 대본을 쓰기 전에 반드시 읽는다.
- **왜 팩트체크 단계가 따로 있는가**: 사주는 해석 체계이지 검증 가능한 예측이 아니다. 그래서 "팩트체크"는
  운명이 실제로 그렇다는 걸 증명하라는 뜻이 아니라, 대본에 등장하는 **역사적 인물의 생몰년, 명리학
  용어의 정확한 정의, 절기/음력 기준일, 통계·설문 수치, 유명인 사례** 같은 검증 가능한 요소가 틀리지
  않게 하라는 뜻이다. 여기서 틀리면 채널 신뢰도가 바로 깨진다.
- **왜 후킹·리텐션 규칙이 구체적인가**: 감으로 쓰지 않기 위해서다. `references/retention-playbook.md`에
  공신력 있는 출처(YouTube 크리에이터 대상 리서치, 심리학 기반 스토리텔링 이론)를 바탕으로 정리해뒀다.
  ①과 ④⑤ 단계에서 이 문서의 원칙을 실제로 적용한다.

## 작업 흐름

사용자가 준 주제 한 줄로 시작해서, 아래 7단계를 **순서대로** 진행한다. 각 단계 결과는 다음 단계의
입력이 되므로 건너뛰지 않는다. 중간 결과를 사용자에게 하나씩 승인받을 필요는 없다 — 끝까지 만든 뒤
완성본을 보여준다. 다만 진행 중 결과를 대화창에 짧게 요약해 보여주면 사용자가 흐름을 따라오기 좋다.

### ① 앵글·후킹

`references/retention-playbook.md`의 1번 원칙(첫 15~30초가 전체를 결정한다)을 적용한다.

- 주제를 시청자 본인 얘기처럼 느끼게 만드는 각도로 비튼다. "OO에 대해 알아보겠습니다" 식 소개는 쓰지 않는다.
- 제목 후보 3~5개를 만들고 그중 가장 강한 하나를 채택한다. 궁금증 갭 + 즉각적 관련성이 동시에 있어야 한다.
- 대본의 첫 문장(=오프닝 훅)을 확정한다. 이 문장은 상담사가 의뢰인이 아니라 사실상 시청자를 겨냥해
  던지는 말이어야 한다.

### ② 팩트체크

웹 검색으로 대본에 넣을 핵심 사실을 검증한다. **추측이나 일반 상식을 사실처럼 나열하지 않는다.**

- 검증 대상 예시: 명리학 용어·개념의 정확한 정의(역마살, 대운, 삼재, 십신 등), 절기 기준일, 음력/양력
  변환 규칙, 인용하려는 통계나 설문, 실존 인물을 예시로 쓸 경우 공개된 사실(생년월일 등).
- 검증이 안 되는 부분(운명 해석 자체)은 사실처럼 단정하지 말고 "사주에서는 이렇게 봅니다", "이런
  구조를 가진 분들이 보통 이런 경향이 있다고 해석해요"처럼 해석 체계로서 서술한다.
- 사용한 출처(URL)를 따로 메모해둔다 — ⑦ 업로드 정보의 "자료출처"에 그대로 쓴다.

### ③ 추가 정보 검색

②에서 근거나 수치가 부족하면 보강 검색한다. 구체적인 사례나 숫자가 하나라도 들어가면 설득력이
확 올라간다 (예: "실제로 이런 시기에 태어난 경우가 통계적으로 몇 % 정도" 같은 구체성). 여기서도
출처를 기록한다.

### ④ 대본 작성

`references/dialogue-format-guide.md`의 규칙을 그대로 따른다. 핵심만 요약하면:

- 화자 비중은 **상담사 70~85% / 의뢰인 15~30%**. 상담사가 정보를 이끌고, 의뢰인은 짧게 되묻거나
  공감 반응하거나 다음 화제로 유도하는 질문만 한다. 의뢰인이 길게 설명하면 안 된다.
- 상담사 어투는 경험 많고 차분한 상담 선생님 톤 — 존댓말, 단정적이되 다그치지 않음. 이모지·밈체·
  과한 느낌표 금지. "너무 가볍지 않게, 그렇다고 딱딱하지도 않게" 중간 무게감을 지킨다.
- 대사만 쓴다. 지문(예: "(웃으며)")은 넣지 않는다 — 스토리보드 단계에서 별도로 다룬다.
- `references/retention-playbook.md`의 오픈 루프·패턴 인터럽트 원칙을 적용한다: 큰 질문 하나를
  초반에 열어두고 후반에 회수하며, 60~90초(약 350~500자)마다 화제 전환이나 새 사례를 넣는다.
- **분량은 화자 라벨과 공백을 제외하고 1,800~2,000자.** 이 단계에서는 대본 텍스트만 깔끔하게
  출력한다 (해설·메모를 섞지 않는다) — 사용자가 그대로 복붙할 수 있어야 한다.

### ⑤ 검토 후 수정

`references/retention-playbook.md`의 체크리스트로 스스로 점검하고, 걸리는 부분은 바로 고쳐서
최종본을 확정한다:

1. `scripts/count_script_chars.py`로 글자수를 확인한다 (`python3 scripts/count_script_chars.py <파일>`
   또는 대본을 stdin으로 넘겨 `-` 사용). 1,800~2,000자를 벗어나면 늘리거나 줄인다.
2. ②③에서 검증한 사실과 대본 내용이 어긋나지 않는지 다시 확인한다.
3. 리텐션 체크리스트(훅 강도, 오픈 루프 회수, 패턴 인터럽트 간격, 문장 길이)를 항목별로 점검한다.
4. 같은 내용을 두 번 말하는 부분이 없는지 확인한다.

### ⑥ 스토리보드

확정된 대본을 씬 단위로 쪼갠다 (대사 1~3줄 = 1씬 정도, 5분 기준 보통 10~16씬).

- 각 씬에 담을 것: 어느 대사 구간인지, 화면에 뭐가 보여야 하는지(한국어로 간단히), 영어 이미지
  프롬프트.
- 이미지 프롬프트 작성 규칙:
  - 영어로 작성.
  - **실사(포토리얼리스틱) 스타일**임을 명시한다 — 예: `photorealistic, cinematic lighting, shot on 85mm lens, shallow depth of field` 같은 톤의 수식어를 일관되게 붙인다. 애니메이션·일러스트 느낌의 단어는 피한다.
  - 실존 인물의 얼굴을 특정해서 생성하도록 지시하지 않는다 (초상권 문제) — "a Korean woman in her
    30s wearing a beige coat" 처럼 일반화된 인물 묘사를 쓴다.
  - 사주 주제와 어울리는 분위기(고요한 상담실, 손금·사주명식표, 창밖 풍경, 은은한 조명 등)를
    구체적으로 담아 실제로 그럴듯한 정지 이미지가 나오게 한다.

### ⑦ 업로드 정보

- **설명(Description)**: 훅 문장으로 시작 → 영상 요약 2~3줄 → 참고 자료 있음을 언급 → 채널/상담
  CTA. 과장 광고 문구는 피한다.
- **자료출처**: ②③에서 모은 URL을 정리해서 리스트로.
- **태그**: 핵심 키워드(주제, "사주", "운세" 등)와 롱테일 키워드를 섞어서 10~15개 정도.
- **고정댓글**: 시청자가 댓글을 달고 싶어지게 만드는 질문형 문장 하나 + 다음 영상/상담 유도 한 줄.

## 최종 결과물 만들기

1. `assets/report_template.html`을 뼈대로 삼아 모든 `{{PLACEHOLDER}}`를 실제 콘텐츠로 채운다. 파일
   상단 주석에 채우는 방법이 적혀 있다 — 특히 `<template id="...-raw">` 안에는 **HTML 태그 없이
   순수 텍스트**를 넣어야 복사 버튼이 깨끗한 텍스트를 복사한다. 각 자리를 직접 읽고 다시 써서
   채운다 (파일 전체에 대한 일괄 문자열 치환은 쓰지 않는다 — 상단 안내 주석 자체가 설명을 위해
   플레이스홀더 표기를 언급하고 있어서 같이 깨진다). 다 채운 뒤에는 상단 안내 주석 블록을 통째로
   지운다.
2. HTML을 직접 새로 디자인하지 말고 이 템플릿의 디자인 시스템(사주 네 기둥 모티프, 다크/라이트
   테마 토큰, 카드·복사버튼 스타일)을 그대로 유지한다. 다만 주제에 따라 문구 톤은 자연스럽게 조정한다.
3. 완성한 HTML 파일을 Artifact 도구로 publish 한다. `favicon`은 🔮 로 고정하고, `title`은 채택된
   영상 제목으로 준다. 이미 완성된 카드형 문서이므로 artifact-design 스킬을 다시 로드할 필요는
   없다 — 다만 템플릿을 크게 뜯어고치고 싶을 때는 로드해서 참고한다.
4. 사용자에게 결과를 넘길 때 "대본 복사", "스토리보드 프롬프트 복사", "업로드 정보 복사" 버튼이
   섹션마다 있다는 걸 짧게 안내한다.

## 주의사항

- 사주는 해석 체계다. 팩트체크는 이론·용어·사례의 정확성에 대한 것이지, 운명이 실제로 그렇다는
  것을 증명하라는 뜻이 아니다. "반드시 이렇게 됩니다" 같은 과장된 확언 대신 "이런 경향이 있다고
  봅니다" 톤을 끝까지 유지한다.
- 실존 인물을 사례로 쓸 때는 공개적으로 알려진 정보만 사용하고, 사생활을 추측해서 단정하지 않는다.
- 사용자가 주제와 함께 타깃 시청자·특정 사례·원하는 톤 같은 부가 정보를 주면 그걸 우선 반영하고,
  없으면 알아서 조회수가 잘 나올 법한 각도로 판단해서 진행한다.
